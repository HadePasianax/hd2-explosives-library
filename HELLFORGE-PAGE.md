# Explosives Library

**Short description:** Shared custom explosions plus built-in HellForge Editor support for custom Explosion, Projectile and Damage Type IDs.

Explosives Library lets compatible mods create independent explosion definitions linked to their own damage records, without changing shared native explosions. Version **0.2.0** adds compatibility with HellForge's **built-in editor**, allowing custom **Explosion / Projectile / Damage Type IDs** to appear and their supported fields to be edited in the existing **Advanced** categories. You do not need to replace the editor generated by the launcher.

## Installation and use

1. Import this ZIP and enable it instead of earlier EL releases/editor labs. Keep exactly one provider enabled.
2. Enable compatible content mods. Put EL before the editor where ordering is configurable, and restart the game.
3. Open **F8 > Advanced > Projectiles / Damage Types / Explosions**, then search the namespace/source name.
4. Confirm input with **Enter/Tab**, then **APPLY/F9**. Resets also need APPLY. Test newly fired shots or redeployed equipment.

Projectile payload fields display named namespace/source references corresponding to their explosion views, rather than only bare IDs. Runtime aliases resolve to real game IDs. Explosion views expose radii and their linked damage fields. Shared definitions affect all projectiles using them.

The library adds no weapons/stratagems by itself. Its editor integration can be disabled with `[editor] enabled=0` in `explosives-library.ini`, followed by a restart. The explosion registry remains available.

## Limitations

- **Multiplayer is unverified.** Do not assume host/client editor synchronization works.
- Records must be registered before the editor reads its catalogue. Late records or unfavorable initialization timing may be absent.
- The **OPS Debug mod** has an unresolved reported pre-APPLY staging issue. Other consumer editing worked in user testing; the OPS cause is not established.
- Persistence after numeric IDs are reassigned or records are renamed remains unverified. Recheck payload-swap selections after changing the mod set.
- Consumer presets may reapply their own stats. Apply presets before editor changes.
- EL explosion views support impact radii and linked damage, not every native explosion field. Native/non-EL explosions use their normal editor entries. Dedicated expiry-explosion edit views are not included.
- Radius order must remain **inner <= outer <= shockwave**. Backend-rejected edits remain rejected.
- **64 unique private explosions** are shared by all consumers. Repeated firing uses no additional slots.
- Visuals/audio are inherited from existing native donors. No new FX/audio import or new status-effect framework.
- Supported game build: **25480438**, SDK **15**, Windows x64. Full cross-session reset/persistence coverage is still limited.

## For developers

Gameplay **ABI 1 remains compatible** with existing consumers. Use namespaced stable keys, register your private damage/projectile records with HellForge, then discover/retry EL and register explosions on the game thread after PROJECTILES_READY. Use returned IDs; never hard-code them. Consumers must implement their own readiness handling.
